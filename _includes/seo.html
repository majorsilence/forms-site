{%- comment -%} All of the metadata that search engines, social cards and AI crawlers read. This is hand-rolled rather than jekyll-seo-tag on purpose. The site is built by actions/jekyll-build-pages, which runs Jekyll in safe mode against its own gem bundle — only plugins that are both in that bundle *and* listed under `plugins:` in _config.yml load at all. Rather than depend on that, everything here is plain Liquid, so what renders in CI is exactly what renders under a local `jekyll serve`. Per-page front matter this reads: seo_title full override (otherwise "<title> · Majorsilence.Forms") description the meta description / og:description. Always set one on a real page — the auto-excerpt fallback produces a snippet from the first paragraph, which is rarely what you'd want shown in a search result. keywords list of phrases, for the meta keywords tag og_image page-specific social card image (site.og_image otherwise) faq list of {question, answer} — emits FAQPage structured data, which is what makes a page eligible for the question-and-answer result treatment noindex true to keep a page out of the index and out of sitemap.xml {%- endcomment -%} {%- if page.seo_title -%} {%- assign seo_title = page.seo_title -%} {%- elsif page.title -%} {%- assign seo_title = page.title | append: " · " | append: site.title -%} {%- else -%} {%- assign seo_title = site.title | append: " — " | append: site.tagline -%} {%- endif -%} {%- if page.description -%} {%- assign seo_description = page.description -%} {%- elsif page.excerpt and page.excerpt != "" -%} {%- assign seo_description = page.excerpt | strip_html | strip_newlines | truncate: 160 -%} {%- else -%} {%- assign seo_description = site.description -%} {%- endif -%} {%- assign seo_description = seo_description | strip_html | strip_newlines | strip -%} {%- assign canonical = page.url | replace: 'index.html', '' | absolute_url -%} {%- assign seo_image = page.og_image | default: site.og_image | absolute_url -%} <title>{{ seo_title }} {%- if page.keywords %} {%- endif %} {%- if page.noindex %} {%- else %} {%- endif %} {%- if page.layout == 'post' %} {%- endif %} {%- comment -%} Structured data. One @graph rather than several disconnected blocks so the nodes can reference each other by @id — that is what tells a consumer the article and the software are the same project rather than three unrelated things that happen to share a page. {%- endcomment -%}
